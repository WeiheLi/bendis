# Bendis on FPGA (Verilog)

`rtl/bendis.v` implements the data plane of `p4/bendis.p4` (count windows) as a pipeline that accepts
one packet per clock cycle. It is cycle-for-packet equivalent to the behavioral model
`src/p4_model.h` with the program's CRC hashes, so it emits exactly the same digests as the Tofino
program.

| stage | work |
|---|---|
| S0 | packet counter: window number, clearing index, bank rotation |
| S1 | CRC hashes (`rtl/bendis_hash.v`, XOR matrices generated by `scripts/gen_hash.py`) |
| S1x | read issue for row 0 (block RAMs have a registered read, two-cycle latency) |
| S2–S4 | counting rows 0–2: conservative increment of the counting bank, read of the previous bank, zeroing of the clearing bank |
| S5–S6 | `c = min`, `p = min`, onset test |
| S7–S8 | onset-table rows 0 and 1: match or stale entry decides (returns the old window), else pass |
| S9 | interval and digest (`R < v <= VMAX`) |

Every bank and table row is a simple dual-port RAM accessed in a single stage. The read of a packet
is issued two stages before its update, so the writes of the two packets ahead of it are forwarded
(the forwarding selects are computed one cycle early).

```bash
make sim BITS=11                       # Verilator testbench (tb/tb_bendis.cpp)
./build/tb_b11/Vbendis trace.t21 --label trace --out rtl.csv   # trace: see the top-level README
make ecp5 BITS=11 FREQ=90              # Yosys + nextpnr, Lattice ECP5-85F (CABGA756)
make xcup BITS=11                      # Yosys synthesis for Xilinx UltraScale+ (estimate only)
```

The testbench streams a trace with a new packet in every cycle, runs the behavioral model in lockstep,
checks that the digest sequences are identical, and scores the digests against the exact ground
truth. On the CAIDA traces, the digests are identical for w = 2^9 to 2^13 entries (13–208 KB), and
place and route on the ECP5 reaches 86.4–95.5 MHz (Table 4 of the paper).
